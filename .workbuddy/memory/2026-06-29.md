## xmake-zed: 修复 debug 支持 + 解决上游 issues #1/#3/#4

分支: main (fork YangZhenxun/xmake-zed), commit 4e3f54c. 准备向上游 xmake-io/xmake-zed 提 PR。

### 关键发现 / 坑 (Zed 扩展开发)
- **WASM 沙箱里 `std::process::Command` 不可用**。Zed 扩展编译为 wasm32-wasip2，要执行外部命令必须用 WIT 提供的 `zed_extension_api::Command`（即 `process::Command`，有 `.output()` 方法调用 host 的 `run-command`）。原 debug 代码用 `std::process::Command::new("xmake")` 静默失败，导致 program 路径永远是 None —— 这是 debug 不工作的根因。
- **`zed::Command` 没有 `cwd` 字段**（WIT `process.command` 只有 command/args/env）。要换工作目录，得在脚本里自己 `os.cd`，把目录当参数传进去。
- **`std::env::current_exe()` 在 WASM 里不可靠**，别用它定位 assets。改用 `include_str!` 把 lua 脚本嵌进二进制，运行时写到扩展工作目录。
- **Zed DAP locator 两阶段**: `dap_locator_create_scenario`(造场景+build 步骤) → 跑 build → `run_dap_locator`(解析真实可执行文件路径返回 DebugRequest) → `dap_config_to_scenario` → `get_dap_binary`。只实现第一阶段会断在 build 之后。
- **底层调试器配置要单独构造**: get_dap_binary 不能把 xmake 包装配置(含 stopAtEntry/debugger/console/label 噪声字段)直接传给 lldb-dap/gdb-dap。lldb-dap 认 `stopOnEntry`，gdb-dap 认 `stopAtBeginningOfMainSubprogram`。
- **Zed tasks.json 格式**: command+args 是 argv 数组，不走 shell，所以 args 里写 `&&` 会被当字面参数。要串联命令用 `command:"sh", args:["-c","a && b"]`。`$argv` 是 VS Code 变量，Zed 没有；用 `${ZED_SELECTED_TEXT:default}`。`$ZED_WORKTREE_ROOT` 会在整个 args 字符串里被替换（包括 heredoc body），所以嵌入 JSON 里别用它，省略 cwd 让其默认 worktree root。
- **扩展只能提供语言绑定任务**（languages/<lang>/tasks.json），没有注册项目级全局任务的 API。issue #4 的解法：提供一个"安装项目任务"任务，把核心任务写到项目 `.zed/tasks.json`（Zed 会全局加载）。

### 改了什么
- src/lib.rs: 重写 debug 三件套(create_scenario/run_dap_locator/get_dap_binary)，用 zed::Command，修复 args 误传。
- src/utils.rs: 嵌入 targetpath.lua，加解析函数。
- assets/targetpath.lua: 接受 projectdir 参数并 os.cd。
- languages/xmake/tasks.json: 全量重写为 Zed 原生格式，修 5 类 bug，去重，加 install task。用 tools/gen_tasks.py 生成 install task(避免手写 JSON 转义错误)。
- extension.toml 版本 0.1.0→0.2.0；README 加 Debugging/Tasks 章节；.gitignore 加 /grammars。

### 构建
